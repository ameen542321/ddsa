# تشغيل واسترجاع مركز القيادة الأمنية

## الإطلاق التدريجي

1. شغّل migrations، واترك `SECURITY_AUTOMATIC_RESPONSE_ENABLED=false` ليعمل النظام في وضع الرصد الآمن.
2. شغّل `php artisan security:health-check` وتحقق من ظهور النبضة في مركز القيادة، ثم راجع البلاغات والفلاتر وخطط الاستجابة.
3. فعّل الاستجابة اليدوية فقط عبر `SECURITY_RESPONSE_ENABLED=true`. لا تفعل الاستجابة الآلية قبل اعتماد المالك للحدود، وهي غير مستخدمة لتنفيذ قرارات تلقائية في الإصدار الحالي.

الإعدادات المعتمدة:

```dotenv
SECURITY_RESPONSE_ENABLED=true
SECURITY_AUTOMATIC_RESPONSE_ENABLED=false
SECURITY_BLOCK_MINUTES=30
SECURITY_EVENT_RETENTION_DAYS=180
```

## دورة التعامل

- يستلم المدير البلاغ ويعين المسؤول.
- ينفذ الاحتواء ويسجل السبب.
- يتبع خطوات الـPlaybook الظاهرة في تفاصيل البلاغ.
- لا يغلق البلاغ إلا بأمر **تحقق وإغلاق** بعد الاحتواء وكتابة نتيجة تحقق مستقلة.
- إذا عاد الأثر، يستخدم **إعادة فتح البلاغ** لإلغاء حالة الحل وإعادته للتحقيق.
- إذا كان الاحتواء تقييد مصدر، يستخدم **رفع تقييد المصدر** للرجوع الفوري قبل انتهاء المدة.

## أوامر التشغيل

- `php artisan security:health-check`: فحص debug والمهام الفاشلة ومساحة القرص وتحديث نبضة المراقبة.
- `php artisan security:weekly-report`: إنشاء تقرير أسبوعي وإرساله كإشعار داخلي للمدير.
- `php artisan security:cleanup --dry-run`: معاينة السجلات التي تجاوزت مدة الاحتفاظ.
- `php artisan security:cleanup`: حذف البلاغات المغلقة التي تجاوزت مدة الاحتفاظ المعتمدة.

## خطة الرجوع الآمنة

- عطّل أوامر الاستجابة فورًا عبر `SECURITY_RESPONSE_ENABLED=false` ثم نفذ `php artisan config:clear`؛ يستمر الرصد والعرض دون تنفيذ احتواء جديد.
- ارفع أي تقييد نشط من أمر **رفع تقييد المصدر** قبل تعطيل الاستجابة، أو امسح Cache التطبيق إذا كانت حالة طوارئ عامة مع إدراك أثر ذلك على بقية Cache.
- استخدم **إعادة فتح البلاغ** إذا ثبت أن الإغلاق غير صحيح؛ يحذف النظام علامة التحقق والحل مع إبقاء سجل الأمر التاريخي.
- لا تنفذ rollback للـmigrations بعد بدء تخزين أحداث إنتاجية إلا بعد نسخة احتياطية، لأن ذلك يحذف حقول التحقق أو جداول الحوادث.

## التحقق بعد الإطلاق

- تأكد أن آخر نبضة فحص حديثة وأن Scheduler يعمل كل دقيقة على الخادم.
- أنشئ بلاغًا تجريبيًا غير حساس وتحقق من ظهوره ومن وصول إشعار البلاغ المرتفع.
- اختبر الاستلام والاحتواء والتحقق وإعادة الفتح في بيئة غير إنتاجية.
- راجع أن الأدلة لا تحتوي password أو token أو cookie أو Authorization أو أسرار البيئة.
- افحص الوضعين المظلم والفاتح والهاتف وسطح المكتب قبل اعتماد الإطلاق.
